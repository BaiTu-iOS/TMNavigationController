# 导航双模式：组件内部切换

日期：2026-11-02。状态：已完成第二次源码复核，尚未实现；三个可行性问题须先用组件内原型验证。

## 目标与范围

目标是在宿主已有系统竖栏能力的前提下，由 TMNavigationController 内部切换标准四个按钮的展示位置。业务继续使用现有 UIButton 属性、页面分类属性和点击回调，不新增模式开关、刷新调用、配置模型或协议。“业务零改动”是验收目标，目前还不是已验证结论。

普通模式继续使用自定义导航栏；系统竖栏模式由页面 navigationItem 承载组件生成的 UIBarButtonItem。最低系统版本保持 iOS 15.1，新竖栏 API 按实际 SDK 和运行系统做可用性隔离。

## 第二次复核结论

保留“原按钮不搬动、组件内部映射”的方向，但上一版有以下遗漏。这里只补设计，不修改业务或组件实现。

前三项通过前，不能将“只改组件即可完整兼容现有调用”作为确定的实施结论。

## 已确认的调用约束

- BTEditingChangeShareIDViewController.m:70 直接使用 RAC 绑定 rightButton.enabled。
- BTSettingLanguageViewController.m:79 为原 rightButton 设置 Masonry 约束。
- BTMomentDetailViewController.m:269 的业务视图依赖 backButton 定位；该页也向 navigationBar 添加独立的关注、更多按钮。
- 多个业务直接设置 titleLabel.font、不同状态的图片和文字颜色；不能只在 UIViewController 分类 setter 中同步。
- 本次已检索的 BTComponent 源码未发现替换四个标准按钮对象的赋值调用。这不代表外部所有调用方式均已验证。

因此保留原 UIButton 对象及其视图层级。系统栏使用展示映射，不把原按钮交给 UIBarButtonItem.customView，也不隐藏整块 TMNavigationBarView。

## 组件内职责

| 位置 | 职责 |
| --- | --- |
| TMNavigationController.m | 判断竖栏布局、协调系统栏显隐请求、管理当前页面系统 items、在导航转场完成或取消后对齐模式 |
| TMNavigationBarView.m | 持有原按钮、同步系统展示、处理整栏显隐与透明度、保留布局位置、区分业务状态与模式导致的不可见 |
| UIViewController+TMNavigationBarView.m | 保留已有对外入口，显隐和状态更新进入组件内部统一路径 |
| 组件私有 UIButton 实现 | 接住直接设置 enabled、hidden、selected、图片、标题等变更；不向业务公开新类型 |

不新增公共 Adapter、Coordinator、配置协议或全局 UIButton swizzle。私有按钮实现用于接收实际控件变更，避免要求业务额外调用刷新。

## 状态和事件

业务仍只维护原按钮。内部将其当前标题、图片、enabled、selected、userInteractionEnabled、可访问性信息和业务显隐状态投射到系统 item。状态分工如下：

| 状态 | 唯一来源及更新方向 |
| --- | --- |
| 按钮业务状态 | 原 UIButton；分类 setter 最终写到该按钮，RAC 和直接赋值也进入同一路径。系统展示只读取，不反向改写业务值 |
| 页面整体显隐 | 现有 navigationBarHidden 入口及自定义 navigationBar 自身显隐；整栏被业务隐藏时，对应的系统映射按钮也不能出现 |
| 模式导致的显示抑制 | 仅组件内部持有，不写回分类缓存，也不冒充业务设置的 hidden、enabled、selected 或 alpha |
| 系统栏承载状态 | TMNavigationController 的实际 UIKit 栏位及当前页面偏好；与页面自定义 navigationBar 是不同对象，不能混用两个同名属性 |

系统模式下只修改 UIButton，不回填分类 associated object。分类已有 getter 的历史语义不在本任务中顺手重构；尤其不能在切回时用这些可能过期的 getter 覆盖原按钮。

原按钮的业务显隐状态与“系统模式下不绘制原按钮”分开保存。切回普通模式时恢复最新业务状态，不能一律 hidden = NO。隐藏原按钮的显示期间仍维护其布局位置，保证现有约束锚点和业务附加视图不受影响；内部布局不能把模式隐藏误认为业务隐藏而跳过位置更新。

这里仍有一个原型门槛：不能用改写 isHidden getter、永久设置 alpha = 0 或 userInteractionEnabled = NO 等办法，掩盖尚未解决的显示隔离问题。源按钮有业务约束时，不能在其约束仍有效的同时强写与之冲突的 frame；只由组件布局的按钮仍走原有 frame 路径。保留对象和父视图本身不等于已经保留约束行为。

现有 setNavigationBarAlpha: 会修改所有自定义栏子视图的 alpha。映射需要覆盖该入口及整栏显隐，alpha = 0 时不能留下可见、可点的系统操作。原生 item 没有与 UIView.alpha 对等的通用属性，连续透明度如何表达也属于展示原型验证范围；不擅自将业务渐变改成二值显隐。

系统按钮点击时转发到原 UIButton 的现有事件路径，继续传入原 UIButton 作为回调参数。不能只调用 click block，以免绕过业务额外注册的 target/action。默认返回沿用已有 pop，业务覆盖返回或关闭回调时继续沿用其行为；系统默认返回项不能与映射后的返回按钮重复出现。

当前四个按钮的组件事件均为 UIControlEventTouchUpInside，转发沿用 sendActionsForControlEvents:，不同时手工调用 block。BTBaseKit 的既有节流仍落在原 UIControl.sendAction:to:forEvent: 路径，不复制节流字段到展示按钮。业务在回调中修改 selected、标题、enabled 或隐藏按钮后，映射读取最终状态；不再让系统 item 自动切换 selected。当前检索未发现标准四按钮的 menu、UIButtonConfiguration 或额外手势调用，不为这些假设新增通用转发框架，也不宣称已覆盖它们。

titleLabel.font、富文本和多行标题等已有样式，在创建映射和进入系统模式时读取。嵌套控件属性变化不会天然经过 UIButton 的 setter；必须验证现有动态修改路径并在组件内部解决更新，不能要求页面调用新的 refresh 方法，也不能声称已自动支持任意 UIView 属性和自定义子视图的复制。

组合状态的标题/图片优先读取原按钮的 currentTitle/currentImage 等有效值，不只复制 Normal 状态，也不自己重造 UIButton 的状态选择规则。原组件图片 setter 清空 titleLabel.text 的路径需先统一为实际 UIButton 内容状态；清空值、图文切换、Disabled/Selected 和按压效果均列为独立用例。UIKit 任意属性的 KVO 能力不能未经验证就作为设计前提。

## 模式切换

1. 统一根页面、push 和已有栈设置入口的导航栏绑定，避免为同一页面重复建立导航栏、系统 item 或监听。createBarView 当前没有像 push 路径一样给页面 navigationBar 赋值，且根页隐藏判断使用 count == 0；先确认实际初始化顺序，不能从创建了一个 barView 推断页面绑定已完成。复用页面时不再执行会清空业务显隐配置的默认初始化。
2. 使用本机 SDK 的 verticalBarEdge 与 systemTraitsAffectingVerticalBarEdge 获取系统布局偏好并跟踪变化；不按机型、屏幕宽度或铰链角度猜测。verticalBarEdge 不代表竖栏已经可见，组件仍需协调系统栏显隐和页面偏好。
3. 进入系统模式时，从原按钮最新业务状态更新左右 items；返回、关闭保持 leading 语义，右侧操作保持 trailing 语义。按 SDK 设置竖栏展示偏好，实际位置交由 UIKit 决定。
4. 系统模式期间，业务更新原按钮会同步反映到系统展示，原按钮仍留在原页面布局中。
5. 退出系统模式时按对象身份移除本组件创建的 items，恢复普通模式展示。不通过恢复进入时的整份数组来覆盖当前 navigationItem；非组件 item 的相对顺序和后续业务更新应保留。每个页面只持有自己的映射，后台页面更新不能写入当前 topViewController 的 items。已检索到的系统 item 调用包括独立的图片、录制及调试容器，不能未经路由确认就把它们都算作 TM 管理页面；不对所有 UINavigationItem 安装全局拦截。
6. push、pop、popTo、setViewControllers、present/dismiss、交互返回取消及切 Tab 后重新显示，都以实际当前页面重新对齐；不重建业务页面，不重复发送业务回调。只让当前受 TM 管理的页面参与，多个导航栈和多个 Scene 不共用全局模式状态。
7. 转场开始前准备目标页面的映射，配合现有 transitionCoordinator 更新；结束或取消后按最终页面校正。不能只在 didShow 后安装，否则会有过渡期按钮缺失或闪动；也不能抢占外部导航 delegate。开合期间遇到转场，最终采用当前 trait 和实际可见页面，不能恢复转场开始时的过期模式。
8. 保留既有 navigationCanDragBack、navigationCanSideslipBack 和自定义 pan 的行为，不因展示系统返回项就重新打开另一套 interactivePopGestureRecognizer。根页、业务自定义关闭、交互返回取消分别验证，不能统一改为系统默认 pop/dismiss。

## 保持的边界

- 迁移范围是 backButton、leftButton、rightButton、rightFirstButton。业务额外添加的头像、关注按钮等保留在原自定义栏，不自动推断它们的导航语义。
- 本轮只切换按钮承载位置，不顺带改变自定义标题、背景及业务内容的布局规则。
- 系统栏显隐引起的 safe area、标题重复和系统横栏占位，需要在组件内验证；不能要求各页面补 inset 或单独处理模式。原自定义标题仍保留时，不再自动向系统栏复制第二份标题；现有 navigationItem.titleView、搜索等内容不能被无条件清空。先确认同页真实混用，再限定接管的属性。
- 宿主 Scene、方向能力或父容器禁用竖栏属于组件外前提。本方案不修改宿主；能力受限时维持可用的自定义展示，并明确记录该场景未进入系统竖栏。

## 所有权与无障碍

- 映射以页面/导航栏实例为单位，系统操作经弱引用指向原按钮；按钮的私有变更通知也不强持有导航栏或页面，避免 page → item → action → page 的环。
- 页面移出导航栈、替换绑定或销毁时，移除属于该绑定的映射和观察。退出系统模式时需要的解除与页面销毁时的解除沿用同一生命周期，不重复注册或重复清理。
- 两个模式只能有一份可命中、可被 VoiceOver 访问的按钮。保留布局占位不意味着旧按钮仍可被辅助功能聚焦；还需验证切换时的焦点延续、label、hint、traits 和 identifier。
- 竖栏空间不足时可能压缩或收纳按钮。四个按钮、长文案、RTL、键盘出现和多行标题都需验证操作仍可达；VerticalPreferred 不是显示保证。

## 实施顺序与原型门槛

先在组件 Example/测试中验证三件事：旧系统栏显隐调用与竖栏共存；原按钮显示隔离且状态/约束有效；真实按钮样式在系统竖栏中的表达。原型不修改外部业务，也不新增业务开关。

三项通过后，再落地统一状态路径、导航生命周期和组件回归测试；最后用已查到的真实调用页面做宿主回归。如果某项需要更改业务接口或宿主才能满足，记录具体阻点，不能自行扩大范围或把未完成的兼容工作转给业务调用方。

## 验收条件

- 现有业务源文件、公开头文件和调用方式无需改动。
- 首次进入已处于竖栏布局时即展示正确；连续切换不重复创建 items 或监听。
- 页面整体隐藏、直接设置系统栏隐藏、自定义栏直接显隐和整栏透明度分别生效；普通模式不被这些适配分支改变。
- 切换期间修改 enabled、hidden、selected、标题、图片和点击回调，两个模式都反映最新状态。
- 图片替换文字、内容清空、Disabled/Selected 组合及回调内更新均正确；分类缓存不会把直接更新的按钮改回旧状态。
- 原本隐藏的按钮切回后仍隐藏；系统模式下新增的业务显隐变化不丢失。
- RAC 绑定、原按钮约束、依赖按钮定位的业务视图仍有效；附加业务控件不被整体隐藏。
- 点击回调只有一次，参数仍为原按钮；验证既有点击节流和 target/action 行为。
- 返回、关闭、push/pop、交互返回取消、RTL、普通设备及最低系统均保持原行为。
- 根页、setViewControllers、popTo、临时导航代理、modal 覆盖、多个导航栈、转场中开合均按最终页面恢复；后台页面更新不串到前台。
- 页面移出栈后可释放，模式切换不增加 retained 页面、观察或 action；无障碍和触摸只保留当前一份入口。
- 真实 Duo 宿主中核验系统栏实际可见、没有重复按钮或标题、安全区没有被重复占用。编译和裸视图测试不能替代该项。

本设计依据当前源码与本机 UIKit SDK 声明；尚未执行双模式原型或运行验收，不能据此承诺所有业务自定义导航内容均已兼容。
